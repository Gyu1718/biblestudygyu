# 성경책 연구 서가 제작 매뉴얼

> 저장소: `Gyu1718/biblestudygyu`  
> 기준 페이지: `ot/esther/index.html`  
> 적용일: 2026-07-25  
> 표준형 적용 대상: 느헤미야, 학개, 로마서 및 앞으로 추가되는 일반 성경책 연구 세트  
> 예외형: 시편, 호세아  
> 기준 사례 보존: 에스더

## 1. 목적

각 성경책의 자료를 하나의 책별 서가 홈페이지에서 일관되게 찾도록 한다. 사용자는 어떤 책을 열어도 다음 순서로 이동할 수 있어야 한다.

1. 성경 읽기
2. 종합 개관
3. 장별 심층연구
4. 원어 연구

연구가 아직 없는 영역도 구조에는 표시할 수 있지만, 실제 파일이 없을 때는 링크를 만들지 않는다. `준비 중`이나 `미구현` 상태를 명확히 표시한다.

## 2. 표준 정보 구조

### 2.1 서가 홈페이지

경로:

```text
ot/<book>/index.html
nt/<book>/index.html
```

필수 섹션 순서:

```text
상단 내비게이션
히어로
읽기와 연구
성경 본문 바로가기
장별 연구 서가
장별 자료 현황
자료 출처 또는 주석 범례
푸터
```

### 2.2 네 단계

#### ① 성경 읽기

공통 성경 리더를 사용한다.

```text
../../bible/original.html?book=<BOOK_CODE>&chapter=1
```

- 모든 장을 처음부터 활성화한다.
- 연구 진행 여부와 무관하다.
- 구약은 WLC/OSHB, 신약은 NA28, 한국어는 저장소의 개역개정 런타임 데이터를 사용한다.

#### ② 종합 개관

표준 파일:

```text
overview.html
```

권장 목차:

1. 책의 위치와 명칭
2. 저자와 연대
3. 역사·사회·문화적 배경
4. 본문과 전승
5. 문학 구조
6. 장별 개요
7. 중심 신학
8. 정경적·복음적 연결
9. 해석사의 쟁점
10. 참고문헌

#### ③ 장별 심층연구

표준 파일:

```text
ch01.html
ch02.html
...
```

권장 목차:

```text
0. 단락의 짜임
1. 단락별 절 범위 주해
2. 핵심 원어와 문법
3. 주석가별 쟁점
4. 역사·문화적 배경
5. 상호 참조
6. 정경적 연결
7. 신학 종합
8. 설교·교육을 위한 메시지
```

왼쪽 사이드바를 사용하는 문서는 모든 장 이동 링크를 실제 HTML에 넣는다. 현재 장은 `aria-current="page"`로 표시한다. CSS나 자바스크립트가 버튼을 대신 생성하게 하지 않는다.

#### ④ 원어 연구

사용자 화면의 명칭은 `원어 연구`로 통일한다. 기본 저장 경로는 다음과 같다.

```text
parsing/ch01.html
parsing/ch02.html
...
```

한 문서에서 다음 요소를 통합할 수 있다.

- 원문
- 음역
- 축자 대역
- 형태론 파싱
- 표제어와 어근
- 구문 기능
- 문장 단위 관찰
- 번역 비교

새 책에서는 별도의 `interlinear/` 폴더를 만들지 않는다. 기존 느헤미야의 `interlinear/`는 호환성을 위해 보존하지만, 새 기본 진입점은 `parsing/`이다.

## 3. 파일 구조

표준형:

```text
ot/<book>/
├── index.html
├── overview.html
├── ch01.html
├── ch02.html
├── ...
├── parsing/
│   ├── ch01.html
│   └── ...
└── README.md                 선택
```

신약도 동일하다.

```text
nt/<book>/
├── index.html
├── overview.html
├── ch01.html
├── ...
└── parsing/
```

실제 내용이 없는 `chNN.html`이나 `parsing/chNN.html`은 만들지 않는다. 빈 페이지 대신 서가 홈페이지에서 비활성 상태로 표시한다.

## 4. 서가 홈페이지 구현 규칙

### 4.1 공통 자산

표준형 서가 페이지는 다음 자산을 불러온다.

```html
<link rel="stylesheet" href="../../assets/theme.css">
<link rel="stylesheet" href="../../assets/app.css">
<link rel="stylesheet" href="../../assets/css/bible-reader.css" data-bible-reader-css>
<link rel="stylesheet" href="../../assets/css/book-shelf.css">

<script src="../../assets/app.js"></script>
<script src="../../assets/js/bible-reader.js" defer data-bible-reader-js></script>
```

본문에는 문맥 정보를 둔다.

```html
<body
  class="book-shelf-page"
  data-book="nehemiah"
  data-kind="study-home"
  data-root="../../"
  data-script="heb">
```

`data-script` 값:

```text
heb  구약 히브리어·아람어
grk  신약 헬라어
```

### 4.2 실제 링크 원칙

완성된 문서:

```html
<a href="ch01.html">...</a>
```

미완성 문서:

```html
<span role="note" aria-disabled="true" class="... disabled">...</span>
```

다음을 금지한다.

- `href="#"`로 준비 중 페이지 표현
- 존재하지 않는 파일 경로 연결
- CSS만으로 링크를 숨겨 오류를 가리는 방식
- 자바스크립트가 실행되어야만 핵심 장 이동이 보이는 방식

### 4.3 상태 명칭

다음 세 상태만 사용한다.

```text
완성
일부 구현
준비 중
```

`완성`은 모든 약속된 파일이 실제 저장소에 있을 때만 사용한다. 로컬 패키지나 대화 중 산출물이 있어도 저장소에 없으면 `완성`으로 표시하지 않는다.

### 4.4 장별 본문 버튼

각 장은 공통 성경 리더로 연결한다.

```html
<a href="../../bible/original.html?book=NEH&chapter=1">...</a>
```

- 두 자리 장 번호를 표시한다.
- 짧은 장 제목을 함께 둔다.
- 모든 장을 활성화한다.

### 4.5 책등

- 종합 개관은 넓은 금색 책등을 사용한다.
- 완성된 장별 심층연구는 파란 책등으로 링크한다.
- 미완성 장은 회색 처리된 비활성 책등으로 표시한다.
- 모바일에서는 세로 책등을 가로 카드로 전환한다.

## 5. 장별 심층연구 사이드바 규칙

상단 순서:

```text
← 책별 서가
서고 홈
성경읽기
원어 연구 또는 원어 연구 준비 중
```

그 다음:

```text
책 이름 + 현재 장
문서 유형
장 이동
전체 장 버튼
현재 문서 목차
```

장 이동 버튼 예:

```html
<div class="chapter-jump">
  <a href="ch01.html">1</a>
  <a href="ch02.html" aria-current="page">2</a>
  ...
</div>
```

성경읽기 링크는 현재 장으로 직접 연결한다.

```text
../../bible/original.html?book=ROM&chapter=2
```

원어 연구 파일이 없으면 링크 대신 텍스트 상태를 둔다.

## 6. 예외형 책

### 6.1 시편

시편은 150편을 다섯 권의 정경 구조로 연구하므로 현재 권별 서가를 유지한다. 표준형 장별 책등으로 강제 변환하지 않는다.

### 6.2 호세아

호세아는 기존 통합 연구 노트 구조를 유지한다. 별도 지시가 있기 전까지 표준형으로 재편하지 않는다.

### 6.3 에스더

에스더는 표준형의 시각·정보 구조를 정하는 기준 사례다. 현재 작업에서는 수정하지 않는다. 이후 장별 자료가 추가되면 기존 비활성 상태만 실제 링크로 전환한다.

## 8. 카탈로그 갱신

책의 상태를 바꾸면 `catalog.js`도 같은 커밋에서 수정한다.

확인 항목:

- 제목
- 원어 표제
- 설명
- 구현된 장 수
- 원어 연구 상태
- 완료 여부

카탈로그의 설명은 저장소 실제 상태와 일치해야 한다.

## 9. 검증 체크리스트

### 링크

- 서고 홈
- 성경읽기
- 개관
- 활성 장별 심층연구
- 활성 원어 연구
- CSS·JS 상대경로

### 상태

- 없는 파일이 활성화되지 않았는가
- 실제 완성 장 수와 배지가 일치하는가
- 현재 장의 `aria-current`가 정확한가
- 비활성 요소에 `aria-disabled="true"`가 있는가

### 문서

- `README.md`의 현황표를 갱신했는가
- `catalog.js`를 갱신했는가
- 작업자가 `AGENTS.md`와 이 문서를 읽었는가

### 화면

- 데스크톱 책등
- 모바일 가로 카드
- 다크 모드
- 키보드 포커스
- 인쇄
- 연구 도크와 플로팅 버튼 겹침

## 10. 새 책 작업 절차

1. 책 코드와 장 수를 확인한다.
2. 책 폴더를 만든다.
3. `overview.html`을 먼저 작성한다.
4. `index.html`에서 모든 장의 성경읽기를 활성화한다.
5. 실제 존재하는 심층연구 파일만 활성화한다.
6. 원어 연구는 `parsing/` 아래에서 시작한다.
7. 공통 자산을 연결한다.
8. `catalog.js`와 `README.md`를 갱신한다.
9. 링크·앵커·중복 ID를 검사한다.
10. 배포 후 GitHub Pages에서 강력 새로고침으로 확인한다.

## 11. 금지 사항

- 출처 확인 없이 주석 내용을 창작하지 않는다.
- 사용자 제공 원문 자료를 공개 저장소에 원본 파일로 올리지 않는다.
- EPUB·PDF·DJVU·폰트 파일을 배포하지 않는다.
- WLC/OSHB를 BHS라고 표기하지 않는다.
- SBLGNT를 NA28이라고 표기하지 않는다.
- 미완성 파일을 완료로 표시하지 않는다.
- 에스더·시편·호세아의 구조를 별도 요청 없이 변경하지 않는다.
